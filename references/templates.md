# 对话类型结构模板

5 种对话类型的结构骨架。判断类型后取对应骨架，按实际内容填充。章节编号非必须，语义标题更自然。

## 1. 技术决策型

强信号：「要不要用 X」「方案 A vs B」、取舍讨论多。

```markdown
## 背景
（一段话：要解决什么问题，为什么需要决策）

## 方案对比

| 方案 | 优点 | 代价 |
|---|---|---|
| 方案 A | ... | ... |
| 方案 B | ... | ... |

## 取舍
（为什么选 A 不选 B--决策依据，这是最有价值的部分）

## 结论
（最终决定 + 一句话理由）

## 关键代码/方案（如有）
```

## 2. 知识问答型

强信号：概念解释、「X 是什么」「为什么」。

保留问答感，每个 Q&A 独立成节：

```markdown
## Q1：<问题>
<精炼的回答，去掉铺垫>

## Q2：<问题>
<精炼的回答>

...

## 小结（如有）
（跨多个 Q&A 的共性认知）
```

## 3. 调试排错型

强信号：报错、定位、尝试解法。

```markdown
## 问题
（现象描述 + 报错信息）

## 排查过程
（关键排查步骤，浓缩失败尝试--只保留有学习价值的）

## 根因
（真正的原因，加粗）

## 解法
（最终有效的解决方案，可复制的命令/代码）

## 防范（如有）
（如何避免再次发生）
```

## 4. 头脑风暴型

强信号：发散想法、「还有没有别的思路」。

```markdown
## 议题
（讨论的核心问题）

## 想法清单
- 想法 A：...（+ 评价）
- 想法 B：...
- 想法 C：...

## 决策
（从清单里选了什么，为什么）

## 下一步（如有）
```

## 5. 代码实现型

强信号：写代码、重构、实现需求。

```markdown
## 需求
（要实现什么）

## 设计要点
（关键设计决策和理由，不要堆全部细节）

## 代码
（可直接复用的完整代码，带必要注释）

## 踩坑（如有）
（实现过程中遇到的坑和解法）
```

## 混合对话处理

一次对话跨多个主题时：
- 按主题分多个 `##` 小节，每节用匹配类型的结构
- 但全文定一个主类型（`conversation_type` 字段），通常是占比最大或最有价值的部分
- 次要类型作为小节嵌入，不单独设 frontmatter

例：一次对话先讨论方案选型（技术决策），再实现代码（代码实现）。主类型定"技术决策"，代码部分作为「关键代码/方案」章节嵌入。
